# Languages and translation maintenance

FALSEWAKE v0.3 supports English (`en`), Simplified Chinese (`zh-Hans`), Spanish (`es`), and Japanese (`ja`) in both the night sandbox and sealed casebook. Use the labelled language selector in either header. The preference is shared across the two modes; selecting a language redraws the current screen without reloading or restarting the investigation.

## What is localized

Navigation, actions, confirmation dialogs, accessibility labels, loading/failure states, role names/abilities/hints, character epithets, historical evidence, case descriptions, sealed statements, reasoning hints, rules, deduction results, debriefs, and replay UI. Character proper names and the FALSEWAKE brand stay the same across languages, so a named witness stays recognizable. User-written notes are never translated.

The original static `noscript` fallback is English because no JavaScript runs to select a locale. Browser-generated technical diagnostics may be in the browser's own language; the application's surrounding error message is translated. These translations are an initial editorial pass, not a claim of independent native-speaker review.

## Selection and persistence

Priority: supported `?lang=` URL parameter, saved preference, the first supported entry in `navigator.languages`, then English. Example: `casebook.html?lang=ja#case=2`.

Regional English/Spanish/Japanese tags resolve to their supported base. `zh`, `zh-CN`, `zh-SG`, and `zh-Hans` variants resolve to Simplified Chinese. Traditional Chinese is not silently relabelled as Simplified; unsupported variants fall through to the next preferred language or English. An invalid stored value or URL is ignored. Blocked browser storage does not prevent in-memory language switching.

The only new storage key is `falsewake.language.v1`. Existing `falsewake.case.v1` and `falsewake.sealed.v1.*` saves remain unchanged. Language, translated text, and personal notes never become rule inputs. Both C++ cores, numeric ABIs, case IDs, and replay schemas are unchanged. Old commands can be replayed in any supported language with identical state and solver results.

## Catalog structure

`web/i18n.js` is shared by both modes and the presentation adapters. `web/locales/{ui,game,help}.js` contain message rows:

```js
// English/source ID, Simplified Chinese, Spanish, Japanese
['Language', '...', '...', '...']
```

The English string is the stable message ID (a gettext-style source-language key). Row order is irrelevant; the runtime builds dictionaries by key. There are currently 480 unique messages, grouped for review. Do not change a source key without updating its callers. Missing translations fall back to the English source. `missingMessages` is exposed by the module for coverage tests, not rendered as game evidence.

`t(id, params)` returns plain text. `tr(id, params)` produces escaped HTML with only catalog-owned, attribute-free `strong`, `em`, `kbd`, `code`, and `br` formatting. `ta(id, params)` escapes attribute text. Parameter values are escaped separately and can never introduce markup. Keep placeholders exactly, including automatically extracted positional names such as `{p1}`; do not translate, delete, or invent them. Whole-sentence templates preserve word order and avoid concatenating English grammar. Singular/plural messages are separate where needed. Numbers and name lists use `Intl` for the active locale.

Rule identifiers and family filters remain canonical, never translated. The grimoire searches both original English and translated role names/descriptions; accents are normalized. All catalogs and fonts are local/system resources, with no translation service, CDN, telemetry, or runtime dependency.

## Adding another language

1. Add its canonical language tag and autonym to `LOCALE_CODES` and `LANGUAGE_NAMES` in `web/i18n.js`; extend `normalizeLocale` deliberately.
2. Add one translation column to every catalog row. Keep all placeholders and allowed inline tags. Never infer hidden identities or reinterpret count rules while translating.
3. Review the distinctions between true team, registration, claimed identity, and report truth. Preserve the separate meanings of Drunk (permanent role) and Taint (temporary impairment).
4. Add the locale to the browser matrix in `scripts/i18n-browser-test.mjs` and inspect real screenshots at desktop and 390/320px widths. For right-to-left languages, implement direction-aware layouts first; current languages use `ltr`.
5. Run `npm test` and `npm run test:browser`. Do not claim full support for a partial catalog.

## Tests

`tests/i18n.test.mjs` checks catalog completeness/uniqueness, placeholder and markup parity, locale negotiation and fallback, escaping, role/event coverage, localized search and formatting, unchanged WASM snapshots, and cross-language replay/solution parity.

`scripts/i18n-browser-test.mjs` runs real Chrome over the `/FALSEWAKE/` HTTP subpath. It checks live switching without lost notes/actions, shared preference across modes, localized roles/search/help, both case proof-to-victory flows in all languages, hints/rules/debriefs, missing message IDs, and 1440/390/320px layouts. Screenshots join the existing CI artifact. A restricted environment may block browser navigation; that is a test failure, never silently reported as a pass. CI must complete the actual HTTP suite before Pages deploys.

Localization is a presentation milestone. It does not expand the solver's proof scope, implement new roles, or produce an Android APK.
